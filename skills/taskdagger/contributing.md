# Contributing to taskdagger / taskdagger

## Contact & feedback

- **GitHub**: [github.com/swordsman/taskdagger](https://github.com/swordsman/taskdagger) — issues, PRs, discussions
- **Bug reports**: Open a GitHub issue with what broke, what you expected, and any relevant work orders or contract hashes
- **Feature requests**: GitHub issues or discussions

## How to contribute

### Feedback
If something breaks, is confusing, or could be better — say so. File an issue. Every failure report makes the system more resilient for everyone.

### Contract fulfillments
Fulfilled contracts (verified implementations indexed by contract hash) are designed to be shareable. If you've built something that satisfies a common contract, consider contributing it to the public contract archive. Your implementation becomes a cache hit for the next person who needs the same interface — zero work, zero tokens, verified result.

### Spec improvements
The reference specs in this skill evolve based on real-world usage. If you find ambiguities, missing edge cases, or better ways to express something — PRs welcome.

### Wanted contracts
We maintain a list of contracts we'd like fulfilled. If you're looking for something useful to build, check the issues tagged `wanted-contract` on GitHub. Each one is a self-contained work order — pick one up, implement it, submit the result.

## Philosophy

This is a public utility. Not copyrighted, not copylefted. Use it, copy it, modify it, share it. If you find it useful, consider contributing back — more contracts, better specs, bug reports, whatever you've got. Somebody's gotta make things better, and it might as well be you.
